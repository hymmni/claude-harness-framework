현재 세션의 작업 재시작을 예약한다. 리셋 시각은 `/usage`로 공식 조회하며(추정 아님), 사용자가 다른 시각을 주면 그 값을 쓴다.

## 흐름

1. **사용자에게 확인** — "지금까지 작업을 정리하고 세션 리셋 시각에 이어서 예약할까요? (다른 시각을 원하면 알려주세요)"

2. **continuation_plan.md 작성** — 프로젝트 루트(`./continuation_plan.md`)에 기록한다. 스크립트가 이 경로를 자동으로 읽는다:
   ```markdown
   # 세션 연속 계획 — {날짜 HH:MM}

   ## 완료
   - ...

   ## 중단 위치
   - 파일/함수/단계: ...

   ## 다음 세션에서 할 일
   1. ...

   ## 주의사항
   - ...
   ```

3. **예약 실행** — 세션 ID·권한 모드는 스크립트가 자동 처리한다:
   - **기본 (세션 리셋 시각에)** — 인자 없이 실행하면 `/usage`로 공식 리셋 시각을 조회해 예약한다:
     ```bash
     python3 scripts/schedule_continuation.py
     ```
   - 사용자가 **"N시간 M분 후"** 라고 하면 상대시간 `--in`:
     ```bash
     python3 scripts/schedule_continuation.py --in 2h30m
     ```
   - 사용자가 **정확한 시각**을 알려주면 `--reset-at`:
     ```bash
     python3 scripts/schedule_continuation.py --reset-at HH:MM
     ```
   이어서 할 작업의 복잡도에 맞춰 `--model`을 함께 지정한다 (설계=opus / 일반=sonnet / 단순=haiku).
   스크립트가 출력하는 실행 시각·모델·권한 모드를 사용자에게 그대로 전달한다.
   예: "19:10(세션 리셋)에 sonnet으로 재시작 예약했습니다."

## 금지사항
- continuation_plan.md 없이 예약만 하지 마라 — 재시작 시 컨텍스트가 사라진다.
- **리셋 시각을 손으로 추측하지 마라.** 인자 없이 실행하면 스크립트가 `/usage`로 공식값을 조회한다. 조회 실패 시에만 사용자에게 시각을 물어본다.
- 세션 ID·권한 모드를 수동 입력하거나 추측하지 마라 — 스크립트가 자동 감지한다.
